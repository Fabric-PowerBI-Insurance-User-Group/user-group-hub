# Content and Accessibility Standards

## Conference-Quality Content

Every published item should be accurate, purposeful, audience-aware, visually coherent, and reusable after the live experience. Event content should identify the audience, prerequisites, outcomes, speaker attribution, publication status, and next steps.

## Accessibility Standard

- Use one clear H1 and logical heading hierarchy.
- Write descriptive links instead of “click here.”
- Provide meaningful image alternative text.
- Use readable typography and sufficient color contrast in slides and visuals.
- Do not communicate meaning through color alone.
- Explain abbreviations and specialist terms.
- Review captions and transcripts before publication when feasible.

## Safe Data Standard

- Use synthetic or fully de-identified data.
- Remove names, email addresses, notifications, tenant identifiers, and credentials from demonstrations.
- Review browser tabs, terminal history, environment variables, chat, and screen recordings.
- Never publish attendee lists, shipping information, or private speaker details.

## Publication Gate

- [ ] Technical review complete
- [ ] Speaker or contributor approval documented privately
- [ ] Rights and attribution confirmed
- [ ] Confidential and personal information removed
- [ ] Accessibility review complete
- [ ] Captions checked when applicable
- [ ] User group boundary statement included where relevant
