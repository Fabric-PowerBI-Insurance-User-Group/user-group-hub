## Operating Principles

- Prioritize participant value over event volume.
- Establish sustainable commitments before adding recurring programs.
- Document decisions that affect identity, schedule, privacy, or publishing.
- Protect private information while keeping public community guidance transparent.
- Require learning value and relevant disclosure from speakers and partners.
- Use review gates for privacy, accessibility, intellectual property, and technical accuracy.

## Repository Controls

- Protect the default branch.
- Require pull requests for material public changes.
- Require at least one co-owner approval; seek both for identity, charter, ownership, recording, or data-handling changes.
- Keep both co-owners as default code owners during launch.
- Keep speaker approvals and private operational records outside public repositories.

## Information Classification

| Public | Private or Restricted |
|---|---|
| Charter, calendar, public event details, approved profiles, approved resources | Registration exports, attendee data, private contact data, consent records |
| Contribution standards, public recognition rules, volunteer opportunities | Shipping details, credentials, unpublished recordings, private meeting links |
| Approved slides, demos, captions, and media links | Conduct reports, organizer deliberations, partner negotiations |
